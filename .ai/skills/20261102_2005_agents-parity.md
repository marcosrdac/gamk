# Keeping mother and consumer AGENTS aligned

## Purpose

Maintain one shared instruction contract between this repository's root `AGENTS.md` and `.ai/templates/project/AGENTS.md`, while allowing intentional, user-approved differences for work that only applies to the mother repository.

## Default rule

`.ai/templates/project/AGENTS.md` is the canonical source for shared instructions. Do not edit root `AGENTS.md` by hand; generate it from the consumer template plus `.ai/templates/mother-AGENTS.extensions.md` by following `.ai/workflows/20261102_2200_update-agent-instructions.md`. Mother-only instructions belong in `.ai/`, never under `global/`. The consumer template must not acquire private paths, mother-only project facts, mother-only rule/skill filenames, or requirements to install personal global context. Consumers discover optional shared guidance via `.ai/global/INDEX.md`; follow its “Always Read” entries, including mandatory rules, and relevant available directory categories.

## Mother-only adaptations

If a task appears to require a mother-only difference:

1. Identify the exact proposed difference and why consumer projects should not receive it.
2. Explain the behavior and maintenance cost of keeping the files different.
3. Ask the user whether to approve the mother-only change before editing either instruction file.
4. If approved, record the rationale in `.ai/decisions/`, add it to `.ai/templates/mother-AGENTS.extensions.md`, and regenerate root `AGENTS.md` using the workflow.
5. If not approved or unresolved, keep it out of the mother extensions and move repository-specific guidance into `.ai/rules/`, an applicable skill, or a mother-only workflow.

## Verification

Before completing a task that changes either source, run the generator and its `--check` mode, inspect the generated diff, and test that consumer output contains no mother-only extensions. The installer must treat an existing consumer `AGENTS.md` as a migration signal and must never replace or merge it automatically.
