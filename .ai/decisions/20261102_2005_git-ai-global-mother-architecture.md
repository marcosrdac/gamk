## Decision

Preserve this repository's current `.ai/` structure and evolve it into the canonical source and installer for that structure. The repository-root `global/` directory is the personal/global context source. The mother repository itself uses a tracked relative symlink `.ai/global -> ../global`; consumers receive a local absolute symlink to the current mother checkout, and that consumer link must not be committed.

The root `AGENTS.md` and consumer `AGENTS.md` template should remain aligned by default. A purposeful mother-only adaptation requires explicit user direction and must be documented through a dedicated skill or rule.

On 2026-11-02 the user specified the AGENTS generation model: consumer template is canonical shared content, and the mother root AGENTS is generated by appending a separate mother-only extension source. A mother-only workflow—not a consumer rule—requires running the generator when the template or mother extensions change; it is not part of routine installation. The shared template explicitly consumes `.ai/global/` whether symlink or directory, reads its index and follows “Always Read” entries, and loads relevant available categories. The mother extension instructs agents to read applicable local `.ai/rules/` and consult local skills/workflows. No shared instruction text should be duplicated in the mother extension.

User clarified that the mother-only extension and workflow are local repository material, not global source. Keep the extension under `.ai/templates/` and the workflow under `.ai/workflows/`; do not place either in `global/` or ship them to consumers.

Clarification from the user: this regeneration requirement belongs specifically in a **mother-only workflow**, not a rule. The workflow is for deliberate instruction updates only; normal installation must not invoke generation.

## Installer behavior

- Provide both a read-only `plan` and an `install` path, plus a global-link repair command.
- Before writing anything, `install` performs a conservative preflight over the consumer. Existing `AGENTS.md`, `.ai/`, relevant agent instructions/configuration, or template path collisions are signals requiring migration review.
- If signals are present, installation exits nonzero before any write, lists findings, and explains how to run `plan`. The plan prints a contextual prompt to the terminal with absolute consumer paths, relevant old/new files, the source commit, and instructions to preserve legacy behavior/residue.
- The target project's agent performs the migration, including integration of an existing `AGENTS.md`; installer does not overwrite or auto-merge it. The user then reruns `install`, which revalidates from scratch.
- If no migration signals exist, install can run without `-y` or an interactive authorization prompt. `-y` may support automation but must never bypass conflict checks.
- The consumer manifest stores the source Git URL, full source commit, and structural schema/version, but no machine-specific absolute paths.
- The global upgrade skill uses source diffs only as evidence; it compares against actual target state, explains tradeoffs and legacy reconstruction work per proposed structural change, and asks user approval before each change. No blind structural updates.

## Rationale and alternatives

The legacy `/home/marcosrdac/prj/git-ai-global` installer is a useful implementation reference, but its additive-copy and optional managed-block behavior is not sufficient for projects that already contain meaningful agent context. A conservative no-write preflight and agent-led migration reduce risk of losing or silently distorting project-specific practices.

An absolute path is unavoidable inside a local consumer symlink if it targets a checkout elsewhere. Keeping that path only in the unversioned symlink, with a repair command, avoids embedding machine-specific paths in versioned consumer files. The installer does not alter the consumer's `.gitignore`, `.git/info/exclude`, or Git index; it warns users to ignore `.ai/global` before committing. The mother repository itself tracks its relative `.ai/global -> ../global` symlink without special Git commands. A Git submodule could make the source transportable but adds lifecycle and update complexity; studying that alternative is deferred to backlog.

## Consequences

- Windows is a required platform; PowerShell and symlink/junction behavior must be tested on an actual Windows host before claiming validation.
- The mother repository's tracked relative link is portable only while `global/` remains a sibling of `.ai/`.
- Source-vs-installed divergence should eventually be surfaced by a status/warning mechanism; this remains a backlog item until designed.
- Changes to consumer structure require synchronized template, installer, tests, documentation, manifest/schema, and AGENTS parity updates.
